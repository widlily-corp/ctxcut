# Техническая спецификация (Архитектура 2.0): Проект `ctxcut`

## 1. Введение и назначение

**`ctxcut`** — высокопроизводительный движок на языке **Rust**, предоставляющий средства контекстного AST-среза исходного кода, хирургического AST-патчинга, генерации тестового окружения и индексации архитектуры рабочего пространства для больших языковых моделей (LLM) и AI-агентов (Google Antigravity, Cursor, Claude Code, Cline, Roo Code, ChatGPT).

### 1.1. Главная цель
Полное устранение проблемы «информационного ожирения» (Context Obesity) контекста при работе LLM с кодом:
- Снижение объема передаваемых токенов на **80–92%** при срезах функций и на **90–95%** при обзоре репозитория.
- Сохранение 100% синтаксической валидности, контрактов типов и сигнатур зависимостей.
- Исключение деградации внимания (*Lost-in-the-Middle*) за счёт удаления избыточных тел функций и второстепенного бойлерплейта.

### 2.1. 🚀 1. Smart Traversal & Timeout Guard
- **Игнорирование:** Автоматический учёт правил `.gitignore` и `.ctxcutignore`.
- **Чёрный список вендоров:** Принудительный пропуск `node_modules`, `target`, `.git`, `.venv`, `.pytest_cache`, `dist`, `build`, тяжелых дампов и бинарных файлов.
- **Fast Estimation Scan (`--fast`):** Моментальная эвристическая оценка потенциала оптимизации токенов без глубокого построения дерева AST.
- **MCP Timeout Guard:** Потокоизолированный тайм-аут (по умолчанию 10 000 мс) с гарантированным перехватом паник и возвратом информативной ошибки без краша STDIO-сервера.

### 2.2. 🕸️ 2. Deep Semantic Slicing & Multi-Symbol Batching
- **Межфайловое разрешение:** Автоматический резолвинг относительных и пакетных импортов для TypeScript/JavaScript, Python, Go и Rust.
- **Подъем типов (`TypeHoister`):** Рекурсивный подъем интерфейсов, структур, типов и перечислений до глубины `--depth <N>` с защитой от циклических зависимостей.
- **Стриппинг вызовов (`SignatureStripper`):** Извлечение сигнатур внешних вызываемых функций с полным удалением (100%) их тел.
- **Многосимвольный батчинг (`path:sym1,sym2`):** Извлечение нескольких целевых функций в одном запросе с глобальной дедупликацией типов и зависимостей.

### 2.3. 🧩 3. Framework-Aware Semantic Intelligence
- **Django & DRF:** Извлечение сериализаторов, моделей, классов доступа (`permission_classes`), бэкендов фильтрации и пагинации при анализе методов представлений.
- **FastAPI:** Извлечение Pydantic-схем запроса/ответа, провайдеров `Depends(...)`, параметров `Security(...)`, query- и path-параметров.
- **React & Next.js:** Автоматический захват `Props`-интерфейсов, кастомных хуков (`useAuth`, `useTableSort`) и интеллектуальное схлопывание второстепенных веток JSX с сохранением ключевых дочерних компонентов.
- **Express / NestJS / Spring:** Извлечение DTO запросов/ответов, декораторов контроллеров, цепочек middleware и Guards (`@UseGuards`, `@UseInterceptors`).

### 2.4. 🎯 4. Adaptive Token Budgeting (5-Level Compression)
- Жесткое ограничение бюджета токенов через `--budget <N>` в CLI и MCP.
- Детерминированный 5-уровневый алгоритм деградации (`BudgetCompressor`):
  1. *Level 1:* Удаление комментариев и docstring-документации.
  2. *Level 2:* Схлопывание второстепенных вспомогательных функций в сигнатуры.
  3. *Level 3:* Сжатие объемных тел switch/match ветвлений в заглушки.
  4. *Level 4:* Преобразование поднятых типов в сверхкомпактные `.d.ts` / type-stub декларации.
  5. *Level 5:* Схлопывание реализации целевого символа до сигнатурной заглушки.

### 2.5. 🛠️ 5. Bidirectional AST Patcher
- Хирургическая замена целевого узла в AST по точному диапазону строк и байт (`AstPatcher`).
- Автоматическое сохранение отступов (indentation alignment), окружающих комментариев и типов переноса строк (CRLF / LF).
- Pre-Write Tree-sitter синтаксический guard: проверка корректности AST нового кода до модификации файла на диске.
- Атомарная запись изменений через временный файл для защиты от повреждения данных.

### 2.6. 🧪 6. Isolated Test Context Generator
- Формирование самодостаточного бандла для генерации изолированных юнит-тестов по шаблону AAA (Arrange-Act-Assert):
  1. Реализация тестируемого символа.
  2. Входные и выходные контракты типов.
  3. Сигнатуры внешних вызовов для создания mock / spy заглушек.
  4. Образцы фикстур существующего репозитория (Vitest, Jest, Pytest, Cargo test, Go test).

### 2.7. 🗺️ 7. Workspace Symbol Overview
- Высокоскоростное индексирование структуры всего проекта без чтения и парсинга тел функций.
- Формирование компактной структурной карты символов, типов, классов и маршрутов (сжатие на 90–95%).

### 2.8. 📊 8. Persistent Telemetry & ROI Dashboard
- Автоматическая фиксация каждого среза в append-only файл `~/.ctxcut/metrics.jsonl`.
- Расчёт сэкономленных токенов и долларового эквивалента по трём ценовым категориям LLM ($0.50, $3.00, $15.00 за 1M токенов).
- Интерактивный терминальный дашборд и MCP-инструмент инспекции метрик.

## 4. Спецификация протокола Model Context Protocol (MCP)

### 4.1. Транспорт и протокол
- **Формат:** JSON-RPC 2.0 по стандарту Model Context Protocol (версия протокола `2024-11-05`).
- **Канал связи:** `STDIO` (stdin — входящие JSON-RPC запросы, stdout — исходящие JSON-RPC ответы).
- **Изоляция:** Каждый вызов инструмента оборачивается в рабочий поток с тайм-аутом (`timeout_ms`, по умолчанию 10 000 мс) и блоком `catch_unwind`.
- **Коды ошибок JSON-RPC:**
  - `-32700` — Parse error (невалидный JSON).
  - `-32601` — Method not found (неизвестный RPC-метод).
  - `-32602` — Invalid params (некорректные параметры инструмента).

---

### 4.2. Каталог инструментов MCP (8 Tools)

#### 1. `get_symbol_slice`
- **Назначение:** Извлечение AST-среза одного или нескольких символов с подъемом типов и стриппингом сигнатур.
- **Входные параметры:**
  - `path` (string, обязательный): путь к исходному файлу.
  - `symbol` (string, обязательный): имя символа (`calculateTax`, `OrderService.refund` или через запятую `sym1,sym2`).
  - `depth` (integer, опциональный, def: 1): глубина рекурсивного подъема типов.
  - `budget` (integer, опциональный): лимит токенов для прогрессивной компрессии.
  - `no_types` (boolean, опциональный, def: false): отключение подъема типов.
  - `no_calls` (boolean, опциональный, def: false): отключение сигнатур вызовов.
  - `timeout_ms` (integer, опциональный, def: 10000): тайм-аут выполнения в мс.
- **Ответ:** Текстовый Markdown-срез с BPE-статистикой токенов.

#### 2. `get_diff_slice`
- **Назначение:** Автоматический срез всех функций, измененных в Git working tree или staged.
- **Входные параметры:**
  - `path` (string, опциональный): путь к репозиторию (def: текущая директория).
  - `staged` (boolean, опциональный, def: false): анализ только проиндексированных изменений.
  - `budget` (integer, опциональный): лимит токенов на каждый срез.
  - `timeout_ms` (integer, опциональный, def: 10000): тайм-аут выполнения.
- **Ответ:** Набор Markdown-срезов для измененных функций.

#### 3. `get_workspace_overview`
- **Назначение:** Индексация символов проекта и генерация компактного архитектурного очерка без чтения тел функций.
- **Входные параметры:**
  - `path` (string, опциональный): корень проекта (def: текущая директория).
  - `depth` (integer, опциональный): максимальная глубина обхода директорий.
  - `budget` (integer, опциональный): лимит токенов для очерка.
  - `timeout_ms` (integer, опциональный, def: 10000): тайм-аут выполнения.
- **Ответ:** Иерархический Markdown-список файлов, классов, интерфейсов и функций.

#### 4. `get_route_slice`
- **Назначение:** Поиск и срез обработчика API-маршрута, DTO-моделей и цепочек middleware.
- **Входные параметры:**
  - `method` (string, обязательный): HTTP-метод (`GET`, `POST`, `PUT`, `DELETE`).
  - `path` (string, обязательный): URL маршрута (`/api/v1/orders`).
  - `root_dir` (string, опциональный): корень поиска проекта.
  - `budget` (integer, опциональный): лимит токенов.
  - `timeout_ms` (integer, опциональный, def: 10000): тайм-аут выполнения.
- **Ответ:** Markdown-срез контроллера маршрута и схем данных.

#### 5. `get_test_context`
- **Назначение:** Формирование изолированного тестового контекста с моками и фикстурами.
- **Входные параметры:**
  - `path` (string, обязательный): путь к исходному файлу.
  - `symbol` (string, обязательный): целевой тестируемый символ.
  - `framework` (string, опциональный): тестовый фреймворк (`vitest`, `jest`, `pytest`, `cargo`, `gotest`).
  - `budget` (integer, опциональный): лимит токенов.
  - `timeout_ms` (integer, опциональный, def: 10000): тайм-аут выполнения.

#### 6. `patch_symbol`
- **Назначение:** Хирургическая замена AST-узла функции или класса в файле.

## 5. Правила движка AST-среза (AST Slicing Engine Rules)

### 5.1. Поиск символов и резолвинг
1. **Языковой адаптер (`LanguageAdapter`):**
   - По расширению файла определяется грамматика Tree-sitter: TS/JS, Python, Go, Rust.
   - Выполняется парсинг исходного кода в AST.
2. **Локализация целевого узла:**
   - Поиск верхнеуровневых функций, методов классов (`Class.method`), структур, интерфейсов и перечислений.
   - Поддержка составных запросов через запятую (`fnA,fnB`).

### 5.2. Подъем типов и стриппинг вызовов
1. **`TypeHoister`:**
   - Сканирует все идентификаторы типов в сигнатуре и теле целевой функции.
   - Резолвит их определения локально или через импорты других файлов проекта.
   - Рекурсивно подтягивает вложенные типы до глубины `depth`.
   - Использует `HashSet` посещенных символов для гарантированной защиты от циклических зависимостей (`A -> B -> A`).
2. **`SignatureStripper`:**
   - Находит выражения вызовов внешних функций (`CallExpression`).
   - Извлекает их сигнатуры и заменяет тело на пустую заглушку (`// body stripped`).

### 5.3. Детерминированное 5-уровневое сжатие (`BudgetCompressor`)
Если итоговый срез превышает лимит `--budget <N>`, последовательно применяются уровни деградации:
- **Level 1:** Стриппинг docstring и однострочных комментариев.
- **Level 2:** Сжатие вторичных хелперов в сигнатуры.
- **Level 3:** Схлопывание крупных ветвей switch/match в краткие заглушки.
- **Level 4:** Перевод типов в ультра-компактный `.d.ts` стиль.
- **Level 5:** Сжатие тела целевой функции до сигнатурной заглушки.

## 6. Спецификация AST-патчинга (`AstPatcher`)

1. **Определение границ:** Через Tree-sitter определяются точные границы строки и байтового диапазона заменяемого узла (`start_byte`, `end_byte`).
2. **Pre-Write Syntax Validator:** Замещающий код парсится в AST соответствующим языковым парсером. Если в коде есть синтаксические ошибки (например, незакрытая скобка), операция немедленно прерывается с ошибкой и файл на диске остаётся нетронутым.
3. **Выравнивание отступов (Indentation Alignment):** Определяется отступ оригинального объявления (пробелы или табы) и применяется ко всем строкам замещающего кода.
4. **Нормализация переносов строк:** Сохраняются оригинальные окончания строк (CRLF для Windows, LF для Unix).
5. **Атомарная запись:** Модифицированное содержимое пишется во временный файл и атомарно перемещается на место целевого файла.
