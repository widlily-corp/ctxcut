# Техническое задание (ТЗ): Проект `ctxcut`

## 1. Введение и назначение
**`ctxcut`** — высокопроизводительный CLI-инструмент и MCP-сервер на языке **Rust**, предназначенный для интеллектуального AST-среза исходного кода с целью оптимизации контекстного окна LLM и AI-агентов (Cursor, Claude Code, Antigravity, ChatGPT).

Инструмент решает проблему «информационного ожирения» контекста, сокращая объем передаваемых токенов на **80–90%** при сохранении 100% семантической целостности типов, контрактов и сигнатур.

---

## 2. Архитектура и принцип работы

### 2.1. Конвейер AST-обработки
1. **Target AST Extraction:** Парсинг исходного файла через `tree-sitter`, мгновенное позиционирование и извлечение полного AST-узла целевого символа (функция, метод, класс).
2. **Scope & Dependency Traversal:** Анализ области видимости целевого узла:
   - Входные и выходные типы, generic-параметры.
   - Используемые интерфейсы, структуры, DTO, Enums, Type Aliases.
   - Внешние вызовы методов, функций и обращений к сторонним сервисам.
3. **Type Hoisting (Встраивание типов):** Автоматический поиск файлов объявлений используемых типов по AST-графу проекта и извлечение их полных определений без лишнего шума.
4. **Signature Stripping (Снятие тел вызовов):** Для всех вызываемых внешних функций генерируется сигнатурная заглушка (имя, параметры, возвращаемый тип) с вырезанием 100% тела реализации.
5. **Prompt-Optimized Markdown Generation:** Формирование структурированного Markdown-отчета для промпта LLM.

## 3. Функциональные требования

### 3.1. Ядро AST-парсинга (`ctxcut_core`)
- Поддержка языков: **TypeScript / JavaScript, Python, Go, Rust**.
- Библиотека парсинга: `tree-sitter` со статически слинкованными грамматиками.
- Время анализа файла до 2 000 строк: **< 10 мс**.
- Способность работать без необходимости полной сборки или компиляции целевого проекта.

### 3.2. CLI интерфейс (`ctxcut_cli`)
- Библиотеки: `clap` (derive), `colored`, `arboard`.
- **Команды:**
  - `ctxcut slice <path:symbol> [OPTIONS]`:
    - `--clip`: прямое копирование результата в буфер обмена ОС.
    - `-o, --output <FILE>`: сохранение в файл.
    - Поддержка среза по нескольким символам: `ctxcut slice src/auth.ts:login,register`.
  - `ctxcut diff [OPTIONS]`:
    - `--staged`: анализ только индексированных изменений git.
    - Автоматическое определение затронутых функций и построение контекстных срезов только для них.
  - `ctxcut stats <PATH>`:
    - Статистика потенциальной экономии токенов и затрат по репозиторию.
  - `ctxcut route <METHOD> <PATH>`:
    - Автоматический поиск обработчика маршрута веб-фреймворков и построение среза хэндлера + DTO.

### 3.3. MCP-сервер (`ctxcut_mcp`)
- Протокол: Model Context Protocol (STDIO / JSON-RPC).
- Инструменты:
  - `get_symbol_slice`: извлечение AST-среза по файлу и символу.
  - `get_diff_slice`: извлечение срезов по изменениям git diff.
  - `analyze_token_stats`: анализ экономии токенов.

## 4. Нефункциональные требования и стандарты качества
- **Язык:** Rust (2021/2024 edition).
- **Производительность:** запуск CLI и выдача среза < 15 мс; нулевые GC-паузы.
- **Кроссплатформенность:** Windows, macOS, Linux (x86_64, aarch64).
- **Стандарты кода:** 0 предупреждений `clippy`, строгая типизация, 0 `unsafe` за пределами tree-sitter bindings.
- **Тестирование (AAA-паттерн):** Unit-тесты на каждый язык/грамматику + сквозные интеграционные тесты с эталонными снимками (golden snapshot tests).

---

## 5. План этапов реализации (Milestones)

1. **Milestone 1 — Foundation & Core AST:** Структура workspace, интеграция `tree-sitter`, парсер TypeScript/JavaScript (поиск символа, type extraction, signature stripping).
2. **Milestone 2 — Multi-Language Support:** Поддержка Python, Go, Rust.
3. **Milestone 3 — CLI & Clipboard:** Полнофункциональный CLI с `clap`, поддержкой `--clip`, `-o`, множественных символов.
4. **Milestone 4 — Git Diff Contextualizer & Stats:** Интеграция с `git2` / CLI git, вычисление токенов (bpe / tiktoken-rs), команда `stats`.
5. **Milestone 5 — MCP Server & Distribution:** Реализация протокола MCP (STDIO), документация, CI/CD сборка бинарников.
